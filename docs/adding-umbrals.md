# Adding an Umbral

Species live at `content/umbrals/<species_id>/`. The ID is permanent and independent of
translated names. `ember` contains Brasa (`form_id = ember`) and Ignivar (`form_id = ignivar`).
Renaming a display label never changes references. Each individual carries its own UID,
`species_id`, `form_id` and passive. There is no numeric stage or maximum evolution count.

## Create and inspect a package

```bash
python tools/umbrals.py new glacier --forms frostling glaciant auroral --name 'Geada'
python tools/umbrals.py validate
python tools/umbrals.py gallery
```

`new` refuses an existing folder. It creates an unregistered draft with three form resources,
linear example transitions, both directional definitions, all required animation states, a
power resource per form, a pure trait stub and provenance metadata. It does not fabricate
art. Drafts cannot be registered until their metadata, trait implementation and actual assets
satisfy the gates. To inspect a new draft in the native Godot Inspector, open its `.tres` files;
the gallery previews registered, validated species.

```text
content/umbrals/glacier/
├── species.tres
├── provenance.json
├── mechanics/trait.gd
├── powers/                         # Own icons and other species-wide assets
└── forms/
    ├── frostling/
    │   ├── form.tres
    │   ├── portrait_left.png        # Provided by the author; not generated by the scaffold
    │   ├── portrait_right.png
    │   ├── presentation.tres
    │   ├── animations/left.tres
    │   ├── animations/right.tres
    │   └── powers/glacier_core.tres
    ├── glaciant/...
    └── auroral/...
```

The shipped species retain their original vector portraits as `portrait.svg`. Both directions
reference that asset and declare left mirroring explicitly. Their eight states are named
procedural poses, not newly drawn sprite animations. A new author may supply distinct left/right
art or explicitly approve mirroring; a missing direction is never silently filled in.

## What the Resources contain

- `species.tres`: stable ID, description, element/color, initial form, passive pool, trait ID,
  trait copy, pure implementation script and references to any number of forms.
- `form.tres`: stable form ID, display name/description, trait strength, copies per power,
  explicit full-effect power variants, outgoing evolution transitions and presentation.
- Each evolution transition: stable transition ID, target form ID, minimum encounter,
  optional health cost and optional required passive. Targets belong to the same species;
  duplicate IDs, dangling targets, unreachable forms and cycles are rejected.
- Shared power identity in `powers/<power_id>.tres`: stable ID, name, description, icon
  and presentation action. Each form variant references it and declares cost, typed
  effects and optional signature badge. Forms can add, improve, replace or remove powers.
  There is no automatic `+5` upgrade or assumption that evolution always adds a signature.
- `presentation.tres`: explicit left/right Resources, shared sound ID and authoring notes.
- Each direction: portrait path, mirroring decision, normalized anchors and animation clips.
- Each clip: action ID, procedural/frame mode, duration/loop flag, procedural offset/scale,
  optional frame asset paths and a timed release event/anchor.

Open the migrated `content/umbrals/ember/species.tres` and
`content/umbrals/ember/forms/ignivar/form.tres` as small working examples. Godot's Inspector
edits the typed exported fields; the files remain text and refer to neighboring Resources
instead of embedding the entire species into the catalog.

To add a branch, add a target form and another transition in its source form's `evolutions`.
For example `seedling → middle → crown` and `middle → ashen`. Every eligible transition
produces its own reward choice. Eligibility is checked again on confirmation; health cost
is applied before reward healing. Evolution preserves UID, species and passive and rebuilds
the deck exclusively from the target's power list. The current expedition still has three
encounters; the catalog model does not impose that encounter count on the evolution graph.

## Presentation completeness

Every form/direction must declare `idle`, `move`, `attack_melee`, `attack_ranged`, `defend`,
`heal`, `hurt` and `defeat`. Both directions need normalized `mouth`, `attack_origin`,
`impact_target` and `center` anchors. A ranged attack requires a release event within its
clip duration. Frame mode requires actual frames; all file references are checked on disk.

Combat selects a declared action from the powers cast by each current owner. For simultaneous
powers from one individual, ranged attack takes precedence over melee, defense and healing.
Only ranged releases emit projectiles, from the chosen anchor at the declared animation time.
Projectile travel completes before impact feedback. Defensive/healing poses do not shoot at
the enemy. Cancellation stops current playback and restores the portrait/transform without
undoing an already committed rules action. Reduced motion keeps the semantic event while
removing visual displacement.

The gallery exposes species, every form, both directions, every animation, origin markers,
mode, timing, mirroring and Resource paths. It is a standalone authoring scene, not a game
session. Use it to inspect actual assets; contract checks alone do not approve artwork.

## Traits, provenance and registration

Implement `mechanics/trait.gd` against `scripts/domain/trait_behavior.gd`, and implement
`is_implemented()` only after the effect exists. Traits receive a typed effect, UID, strength,
active count and per-cast context. They cannot import UI, read files, invoke global RNG or
load the catalog. Add independent numerical expected-value tests for every new effect.

Record every source asset and its hash/license/origin in `assets/asset-manifest.json` and
in the package's `provenance.json`. Keep exact original generation metadata and editable
sources. Shared sounds/fonts/environment remain under `assets/`; unique creature/power art
belongs to its species package. `tools/generate_assets.py` remains the editable source of the
original vectors; its historical names resolve via `tools/original-asset-paths.json`.

```bash
python tools/umbrals.py register glacier
bash tools/check.sh
python tools/iterate.py --label glacier --goal 'Validar Geada e suas formas em jogo' --baseline <previous-evidence> --video
```

Registration validates the candidate and its assets before writing readiness or membership,
then appends it to `content/catalog.tres`. Preserve the existing manifest order: seeded capture
rolls depend on that order. Registered drafts and ready-but-unregistered packages fail the gate.
`check.sh` also exercises refusal and successful registration in a disposable project containing
four species and nine forms. It never edits the real catalog for its authoring tests.

The architecture gate scans authored `.tres` dependencies and package trait scripts as well
as production GDScript. Returning to ordinal stages, hiding creature definitions in coordinator
code, omitting a required state or making evolution depend on a translated name is not an
acceptable shortcut. Finish with actual directional/animation review and preserve failed evidence.

## Export contract

Godot 4.6.3's automatic text-to-binary export conversion erased the authored passive pools
in the first Web attempt. Source/native tests alone did not reveal it. The project explicitly
preserves text Resources (`editor/export/convert_text_resources_to_binary=false`). Web export
now loads the actual PCK and compares every authored export field and a seeded initial run
against source. Browser input independently checks the initial individuals/forms/passives.
Do not re-enable conversion or waive this comparison without a verified engine fix.

Form identity is part of the hand-view cache key: changing form must refresh stats even if
all card instance IDs remain the same. A regression test covers this explicitly, along with
a ten-species codex containing long, branched evolution names and a scrollable wrapping grid.

For cloud-rendered gallery evidence, use an isolated project copy with
`scenes/creature_gallery.tscn` as its main scene and export that copy to Web. Official release
Web templates reject command-line scene overrides; do not change the real main scene merely
to capture the tool. Record real-input captures of directions/actions alongside the normal
game iteration. See `species-package-review.md` for the completed migration's evidence.

For power effects, conditions, statuses, items and enemy content, follow
[adding-gameplay-content.md](adding-gameplay-content.md). Shared visual styles and their
component gallery are described in [visual-style.md](visual-style.md).
